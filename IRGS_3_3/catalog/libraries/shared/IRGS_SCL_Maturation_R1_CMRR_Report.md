# IRGS — SCL Maturation R1 | CMRR & Regression Report

**Status:** Proposed additive maturation; Core 3.2 mechanics unchanged; SCL 1.0 catalogue release and immutable `@0.2` record IDs unchanged.

## Compare

Input A: Core 3.2 clean integrated release (user uploaded). Input B: Core 3.1 complete release (user uploaded), including preintegration source registry and provenance materials. All source references are descriptive, not imported campaign state. The Core 3.2 clean archive excludes historical source snapshots and runnable prior suites; this package adds independently executable invariant checks, but does not claim to reproduce the original 84/60 check suites.

**Preservation baseline:** 123 numbered Core topics and eleven Core domains; 279 canonical content families; 286 neutral source rows; 1,416 aliases; 304 source bindings; 420 source payload blocks; 61 Fantasy adapter records; 18 specialized extensions; 22 physical weapon compositions; 51 selected qualitative contracts; 228 source-backed holds. These quantities remain unchanged. The 304 source bindings refer to the current Core 3.2 provider; historical documents are not overwritten. The 18 scoped extensions intentionally have no shared `release_ref` because they are not portable family entries.

## Merge: substantive additions

- 36 source-specific, noncanonical qualitative qualification drafts: 10 material families, 10 coverage descriptors, five network node views, six shield families, five body-plan definitions. Each has nine causal/portable content fields and a distinct example/counterexample.
- The other 192 held entries receive individually keyed remediation records showing source identity, unresolved parameters, a class-specific failure gate and the next acceptance requirement.
- The new qualification files are **standalone opt-in sidecars**. To prevent unknown-field regressions in strict consumers, the normative registry, Core spec, and provider bindings are all byte-identical to the current clean distribution.
- Reproducible Python verification checks now ship with this candidate release, alongside source/identity preservation and data validation.

## Validation and limitations

The accompanying script checks release-file hashes, exact catalogue invariants, alias target/selector integrity, sidecar draft/hold classification, counts, complete draft field coverage, source-ref accounting and individual remediation entries. It also executes bounded miniature demonstrations of no-instantiation, one-stock conservation, and reference continuity. The self-contained package verifier passed **84 of 84 checks** in this build; five deployed contract files were additionally compared byte-for-byte with the uploaded Core 3.2 source. These **are not actual IRGS simulation runtime tests**; mechanical realism, historical accuracy, balancing, and live playtesting remain unverified.

## Future acceptance/promotion

New source-backed records require: source support, complete qualitative content, compatible native model, versioned individual definition/target checksum, selector/alias migration where required, cross-engine feasibility cases, actual runtime tests and approval. Original `@0.2` records and resolved campaign history remain available. Do **not** relabel these 36 drafts selected just because this document exists.

## Migration

No campaign/state migration or adoption. Existing Core 3.2 + SCL 1.0 deployments can ignore this additive R1 overlay without changing any content ID. A later adopted v1.1 catalogue should explicitly pin the new versions, document adapter compatibility and run new suite comparison before any source deprecation.
